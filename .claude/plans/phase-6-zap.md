## Context

ZAP's baseline scan spiders the running app and runs passive rules only (no attacks). Gating rule 6 blocks on "ZAP rules set to `FAIL` in `rules.tsv`". This phase:
- runs the scan locally and reads what it finds;
- writes `.zap/rules.tsv`, every rule IGNORE/WARN/FAIL with a reason;
- writes the findings up and picks one header for phase 8;
- adds a CI job that never fails on findings (triage, phase 7, is the only gate).

## Research (2026-10-12, researcher agent)

- **Image:** ZAP **2.17.0** (released 2025-12-15) is the current stable. The image is rebuilt about monthly with updated add-ons, so `stable` and `2.17.0` both move. The 2026-10-08 rebuild (`20261008-stable`) is `ghcr.io/zaproxy/zaproxy:2.17.0@sha256:7aaa659b0d43078febd82e29bad112285c370727e86ab8340444220e17d9f0d2` (verified with `docker buildx imagetools inspect` 2026-10-12: index digest matches, amd64 manifest 17711b68…, arm64 8836a610…). No advisories for the images or `action-baseline`. Base is Debian bookworm with Firefox + xvfb; runs as `zap` (UID 1000); has `curl`.
- **Exit codes:** 0 = no WARN/FAIL; 1 = at least one FAIL; 2 = WARN, no FAIL (`-I` turns 2 into 0); 3 = exception / bad args / no PASS at all. Unconfirmed: whether an unreachable target exits 3 (it logs "No URLs found").
- **Flags:** `-t` target, `-J` JSON, `-r` HTML, `-c` rules file (relative to `/zap/wrk`), `-g` generate default rules (all WARN; forces the legacy non-automation path), `-j` adds the Client Spider (Firefox, headless), `-m` spider minutes (default 1), `-T` max wait, `-a` alpha rules, `-I`. Confirmed 2026-10-12: `-j` = **Client Spider** with `type: spiderClient` in zap.yaml, maxDuration 1 min.
- **rules.tsv:** tab-separated `<pluginid>\t<LEVEL>\t<name>[\t<custom message>]`; levels IGNORE/INFO/WARN/FAIL (plus `OUTOFSCOPE` with a URL regex). Lines starting with `#` are comments. Keyed by integer plugin ID, so variants (`10038-1` vs `10038-3`) can't get different levels. IGNORE doesn't stop the rule running; it only changes the summary and exit code.
- **JSON report** (`traditional-json`): `site[]` → `alerts[]` with `pluginid`, `alertRef`, `name`, `riskcode`, `confidence`, `cweid`, `count`, `instances[]` (`uri`, `method`, `param`, `evidence`), `systemic`. Numbers are strings. **The WARN/FAIL level is not in the JSON**, and IGNOREd alerts are probably still in it (from reading the source). Baseline caps instances at 5 per rule (not 10; verified 2026-10-12: console showed ×11–18 but JSON `count` capped at 5).
- **Networking:** a container can't reach the host's `127.0.0.1`. ZAP's docs recommend a user-defined network: app container `juice` and ZAP on network `scan`, target `http://juice:3000`. No published port needed.
- **Readiness:** Juice Shop seeds its data before `server.listen`, so the first HTTP 200 on `/` means ready (~12 s in phase 1). The app image is distroless (no curl), so poll from the ZAP image's `curl` on the same network.
- **SPA:** the traditional spider doesn't run JavaScript, so on Angular it sees `/`, bundles, `robots.txt`/sitemap and little else. Alert 10109 "Modern Web Application" says so. `-j` (Client Spider) should find more, at the cost of extra minutes.
- **`zaproxy/action-baseline`:** defaults to the moving `stable` tag, files GitHub issues (`issues: write`), uses `--network host` and `chmod a+w` on the whole workspace.
- **Expected alerts (inferred, not observed):** 10038 CSP not set, 10063 Permissions-Policy, 10098 cross-domain misconfiguration (`cors()` sends `*`), 10017 cross-domain JS, 10096 timestamp disclosure, 10027 suspicious comments, 10109 modern web app, 10015/10049 caching, 10037 X-Powered-By, 90004 Spectre isolation, 90003 SRI missing, 10003 vulnerable JS library, 10202 no anti-CSRF tokens. helmet sets `noSniff` and `frameguard`, so 10021/10020 should be rare. 10035 HSTS unlikely (plain HTTP).

### Add-on research (2026-10-12, researcher)

- **pscanrulesBeta add-on:** holds exactly 6 rules: 10049, 10063, 10110, 90004, 10026, 10099. Current v50 (released 2026-04-14); needs ZAP ≥ 2.17.0 and commonlib ≥ 1.40.0 (image has 1.44.0). URL: `https://github.com/zaproxy/zap-extensions/releases/download/pscanrulesBeta-v50/pscanrulesBeta-beta-50.zap`, 596114 bytes, SHA-256 `a979f7cd5d8be10e0338b417e006ec1e2f6ec79101010d570ddb5199892e921b` (verified against GitHub asset digest and zap-admin ZapVersions-2.17.xml). ZAP loads add-ons from `/zap/plugin` and `/home/zap/.ZAP/plugin`; highest version wins; no hash check is performed. `-z "-silent"` skips add-on update at startup (substring check `"-silent" not in zap_options` in zap-baseline.py, verified in image copy) and in the scan run disables check-for-updates, telemetry and makes 10116 return silently. pscanrulesAlpha (10094, 90005, 110009) requires `-a`, not used here. Uncertain: read-only mount mechanism untested; mounting to `/home/zap/.ZAP/plugin` may create root-owned parent dirs (safer to use `/zap/plugin`, keep the filename).
