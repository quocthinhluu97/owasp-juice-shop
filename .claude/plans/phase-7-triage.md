# Phase 7: Triage script (plan)

Status: **Approved: 2026-10-18** (decisions D4, D7, D9, D12 answered 2026-10-18) · Amendments D19, D20 decided by user 2026-10-18 · Branch: `phase-7-triage` · Pipeline: `.claude/rules/feature-pipeline.md`

## Context

One Python script reads the five scanners' reports, normalizes them to one `Finding` model, dedupes, enriches (KEV, reachability hints), applies waivers, applies gating rules 1–6 (`gating-policy.md`) and reports. It is the only thing that can fail the build. Rules: `triage-script.md`, `gating-policy.md`. Phase-7 notes from earlier phases: `docs/findings/{gitleaks,trivy,semgrep,checkov,zap}.md`.

**Expected:** the first CI run is red. That's the point. Waivers are written by the user, one per judged finding, after reading the report (guide, don't do).

## Research (2026-10-17, researcher agent)

- **Pinned scanner versions in security.yml:** gitleaks 8.30.1, trivy 0.75.0, semgrep 1.179.0, checkov 3.3.22, zap 2.17.0.
- **KEV:** feed `https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json` (CC0; mirror `cisagov/kev-data`). Required top level: `catalogVersion`, `dateReleased`, `count`, `vulnerabilities[]`; entries: `cveID` (`^CVE-\d{4}-\d{4,19}$`), `dateAdded`, `dueDate`, `knownRansomwareCampaignUse` (Known/Unknown), `forensicTriage`, `cwes[]`, … No documented ETag/rate limit; detect changes via `catalogVersion`. Local `reports/kev.json` = 2026.10.02, 1733 entries, matches schema.
- **EPSS:** API `https://api.first.org/data/v1/epss?cve=…` (2000-char limit on the list, 1000 req/min); bulk CSV `https://epss.empiricalsecurity.com/epss_scores-current.csv.gz`. Free, attribution requested, no formal licence.
- **Python/deps:** Python 3.12.15 (security-only). pytest 9.1.1, PyYAML 6.0.3. `actions/setup-python@v7`; `upload-artifact@v7`, `download-artifact@v8` are current majors (v8: `pattern` ignored when `name` set; `merge-multiple` default false).
- **Actions:** `$GITHUB_STEP_SUMMARY` limit 1 MiB per step (over → upload error, job status unchanged). A job whose `needs:` failed is skipped unless `if:` uses a status function; `!cancelled()` is the recommended form (not `always()`). The failed job's artifact won't exist → the script must detect it and exit 2.
- **Trivy JSON:** fs: `Class lang-pkgs`/`Type npm`; image: `os-pkgs`/`debian` and `lang-pkgs`/`node-pkg`. Dev flag never present (no `--include-dev-deps`); `devOptional` lockfile entries (11 root, 82 frontend) are treated as prod by Trivy. fs `Vulnerabilities[]` have no PkgPath/Relationship: join `PkgID` → `Packages[].ID` (Relationship `direct`/`indirect`, `DependsOn`). Image vulns carry `PkgPath`, `Layer`. `Status` fixed/affected; `FixedVersion` comma-separated list. Tell image from fs by `ArtifactType`, never by name.
- **Semgrep JSON:** `extra.severity` ERROR/WARNING/INFO plus newer CRITICAL/HIGH/MEDIUM/LOW (ERROR=HIGH, WARNING=MEDIUM, INFO=LOW legacy aliases). Local: WARNING 29, ERROR 5, MEDIUM 2, INFO 1. `metadata.cwe` = list of `"CWE-798: …"` strings. `extra.fingerprint`/`lines` = `"requires login"`.
- **Checkov JSON:** array of per-framework objects (`check_type`), BUT a single object when only one framework has results, and a summary-only object when none. `failed_checks[]`: `check_id`, `file_path` (leading `/`, relative to scan root), `file_line_range`, `severity` always null.
- **Gitleaks JSON:** keys RuleID, File, StartLine, Secret, Match, Commit, Fingerprint (`commit:file:rule:line`)… Local `reports/gitleaks.json` is a `--redact` run (all Secret = REDACTED) → **not usable as a fixture**; use the CI artifact (Secret = `sha256:<hex>`).
- **ZAP JSON:** riskcode 0–3 → Info/Low/Medium/High; confidence 0 FP … 4 Confirmed; numbers are strings; `alertRef` may carry a suffix, match on `pluginid`.
